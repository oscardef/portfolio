## Overview

I tutor maths on the side, and Mathium started in 2025 as TutorAssist, a tool to make my own tutoring more effective. Instead of assigning practice from a textbook, it generates questions tailored to each student's syllabus and weak areas, then shows me where they need help before our next session.

In 2026 I rebuilt it and renamed it Mathium: a platform for students, tutors and schools rather than just for me.

<Callout type="info" title="In development">
Mathium is in active development and not yet open to the public.
</Callout>

## For Students

- **Practice and assignments** with immediate feedback, hints and worked solutions
- **Proper mathematical input** with MathLive: fractions, matrices, vectors and coordinates, not just typed text
- **Symbolic grading**: equivalent forms of an answer are accepted, not just the exact text
- **Progress over time**, with an activity heat map and streaks

## For Tutors

- **Question bank** with LaTeX, figures and multi-part questions
- **AI question generation**, specifying topic, difficulty and answer format
- **Shared library**: new and edited questions go through review before joining a library that any workspace can import from
- **Syllabus tagging**: library questions are tagged to IB Diploma syllabus points
- **Live session rooms** with a shared whiteboard, and self-service booking for sessions
- **Assignments** with due dates and completion tracking

## Technical Details

**Stack:** Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS

**Data:** PostgreSQL 17 with pgvector. App data is served through PostgREST, and row-level security policies in the database keep each workspace's data isolated.

**Auth:** Better Auth. Requests to PostgREST carry JWTs minted from the user's session, so row-level security applies to every query.

**Maths:** MathLive for input, KaTeX for rendering, Compute Engine for symbolic grading, JSXGraph for figures

**Collaboration:** Excalidraw whiteboard in session rooms

**AI:** OpenAI API for question generation

**Background jobs:** a separate worker container for long-running work such as AI generation

**Hosting:** self-hosted with Docker Compose

## What I Learned

- Building for yourself as the user gives you an unfair advantage in product decisions: I know which features matter because I use them every week
- Mathematical input and grading are surprisingly hard. Comparing answers as mathematics rather than text, across many answer formats, took more work than any other feature
- Moving off Supabase to a self-hosted stack, I kept the existing row-level security policies unchanged by having PostgREST enforce them with JWTs minted from the app's own sessions
